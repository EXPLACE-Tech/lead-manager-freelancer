# lead-manager 初回セットアップ手順

対象: 発注ナビの営業パイプライン管理（Google スプレッドシート + Google Apps Script）
所要時間: 15〜20分。認証はあなた自身の Google アカウントの OAuth 同意で完結する（サービスアカウント不要）。

---

## 0. 事前準備

- コード一式は `gas/` フォルダにある（7ファイル）。エディタで内容を見ながら進める。
- 発注ナビの配信メールを受け取っている Google アカウントで、以降すべての操作を行うこと。

---

## 1. スプレッドシートを新規作成する

1. ブラウザで [sheets.new](https://sheets.new) を開く（新規スプレッドシートが自動で作成される）。
2. 左上のファイル名を「営業パイプライン管理」など分かりやすい名前に変更する。
3. メニューの **拡張機能 → Apps Script** を開く。新しいタブで Apps Script エディタが立ち上がる（これがこのスプレッドシートに紐づく container-bound スクリプトになる）。

---

## 2. コードファイルを貼り付ける

Apps Script エディタで、`gas/` フォルダの各ファイルを1つずつコピペする。

1. デフォルトで `Code.gs` というファイルが1つある。中身を全部削除し、`gas/Config.gs` の中身を貼り付けてから、ファイル名を `Config` に変更する（拡張子 `.gs` はエディタが自動で付ける）。
2. 左メニューの「ファイル」横の `+` → `スクリプト` で新規ファイルを作り、以下を同様に追加する。ファイル名はそれぞれ拡張子なしで揃える:
   - `Parser_HatchuNavi`
   - `SheetWriter`
   - `GmailWatcher`
   - `TemplateHistory`
   - `Setup`
3. マニフェストファイル（`appsscript.json`）を編集できるようにする: エディタ左の歯車アイコン「プロジェクトの設定」を開き、「'appsscript.json' マニフェスト ファイルをエディタで表示する」にチェックを入れる。
4. 左メニューに現れた `appsscript.json` を開き、中身を `gas/appsscript.json` の内容で置き換える（`oauthScopes` に Gmail・スプレッドシート・トリガー権限が入っている）。
5. すべて保存（Ctrl+S）。

ファイル同士の読み込み順は気にしなくてよい（Apps Script は全ファイルを1つのスクリプトとして実行するため）。

---

## 3. 初期セットアップを実行する（シート・プルダウン・集計式の自動構築）

1. Apps Script エディタ上部の関数選択プルダウンで `setup` を選ぶ。
2. 「実行」ボタン（▷）を押す。
3. 初回は **承認が必要です** という画面が出る。
   - 「権限を確認」→ 自分の Google アカウントを選択
   - 「Google で確認されていません」という警告が出るが、自分が書いたスクリプトなので問題ない。「詳細」→「（プロジェクト名）に移動（安全ではないページ）」→「許可」
4. 実行が終わると、ダイアログではなく実行ログに完了メッセージが出る（`setup()` はスプレッドシート UI から呼ばれていないとダイアログが出せないため）。ログに「セットアップが完了しました」と出ていれば OK。
5. 元のスプレッドシートのタブに戻り、リロードする。以下のシートができているか確認する:
   - `案件リスト`（ヘッダー13列、H列＝ステータスがプルダウンになっている）
   - `テンプレート_Web制作` `テンプレート_システム開発` `テンプレート_デザイン` `テンプレート_マーケティング`（各シートA1:B1が見出し、5行目に変更履歴ヘッダー）
   - `集計`（A〜O列に集計式、P列は空欄＝考察メモ用）
6. スプレッドシートをリロードすると、メニューバーに **営業パイプライン** メニューが追加されている。以降のセットアップ・手動チェックはこのメニューから実行できる。

`setup()` は再実行しても安全（既にあるシート・データは壊さず、足りない部分だけ補う）。

---

## 4. 15分ごとの自動チェックを設定する

スプレッドシートの **営業パイプライン → ② 15分トリガーを設定** を実行する（`installTrigger()`）。
確認ダイアログで「15分ごとの自動チェック（checkNewLeads）を設定しました。」と出れば完了。

手動で確認したい場合は、Apps Script エディタ左メニューの「トリガー」（時計アイコン）を開き、`checkNewLeads` が「時間主導型トリガー」「分ベースのタイマー」「15分ごと」で登録されていることを確認する。

---

## 5. 動作確認

1. スプレッドシートの **営業パイプライン → 新着案件を今すぐチェック** を実行する（`checkNewLeads`）。
2. Gmail に `mo-hnavi@ml.itmedia.co.jp` からの未処理メールがあれば、`案件リスト` に1行追加され、ステータスが「配信検知」になっているはず。
3. Gmail 側を確認: 処理したメールのスレッドに `LeadManager/発注ナビ処理済` というラベルが自動で付いている（次回以降は同じメールを二重処理しない）。
4. 未処理メールが無ければ何も起きない（正常）。テストしたい場合は、発注ナビの配信メールを自分宛に転送するか、次の新着配信を待つ。

---

## 6. 運用の流れ

1. 15分ごとに自動で `案件リスト` に新着案件が積み上がる（配信日時・案件No・タイトル・URL・ステータス＝配信検知のみ。**カテゴリ・予算・応募期限は空欄のまま**）。
2. カテゴリ・予算・応募期限は自動で埋まらない。Claude Codeセッションで「lead-manager のリード処理して」と声をかけると、claude-in-chromeでログイン済みの発注ナビタブから案件詳細を読み取って埋めてくれる（手順は `docs/リード処理の手順.md`）。GASでは対応しない（案件詳細ページはログインが必要で、GASからは取得できないことを検証済み）。
3. 応募する案件は、該当カテゴリの `テンプレート_<カテゴリ名>` シートの A2 セル（応募文まるごと1本）をそのまま使うか、案件の内容に合わせて直接編集して仕上げる。ライティング/その他/未分類の案件はテンプレートが無いので、都度ゼロから書く。
4. 応募したらステータスを「応募済」に変更し、応募日を入力。以降、返信・商談・成約/失注の都度、対応するステータスと日付列を更新する。
5. `テンプレート_<カテゴリ名>` シートの A2（内容）を編集すると、5行目以降の変更履歴に自動で1行積み上がる（日付・変更前・変更後）。何をいつどう変えたかは自分で追記しなくてよい。
6. `集計` はカテゴリ別の返信率・商談化率・成約率を COUNTIFS で自動計算する（案件リストのステータス列を見るだけなので、リアルタイムで反映される）。P列の考察メモに気づきを書き留めていく。

## トラブルシューティング

| 症状 | 確認ポイント |
|---|---|
| `setup` 実行時に「ReferenceError: xxx is not defined」 | ファイルの貼り付け漏れ・ファイル名の付け間違いがないか（手順2を再確認） |
| 承認画面で先に進めない | Google アカウントが発注ナビのメールを受信しているものと同じか確認 |
| メールが来ているのに案件リストに増えない | Gmail で `from:mo-hnavi@ml.itmedia.co.jp` を検索し実在するか確認／既に `LeadManager/発注ナビ処理済` ラベルが付いていないか確認（付いていれば処理済み扱い） |
| カテゴリ・予算・応募期限が空欄のまま | 仕様通り（GASでは埋めない）。`docs/リード処理の手順.md` の手順でClaude Codeに処理してもらう |
| トリガーが動いていないか不安 | Apps Script エディタ左メニュー「実行数」で `checkNewLeads` の実行履歴と成否を確認できる |

## コードを更新したとき

`gas/` 側のファイルを直したら、Apps Script エディタ側の同名ファイルに手動で貼り直す（自動同期はしない）。`Config.gs` の `CODE_VERSION` を上げておくと、後で「どのバージョンが貼ってあるか」を実行ログで判別しやすい。
