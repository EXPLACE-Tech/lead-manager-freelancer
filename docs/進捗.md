### スキーマ変更の経緯

- **版2**（社長指示）: シート名の「発注ナビ_」接頭辞を廃止（`案件リスト`/`応募文テンプレート`/`集計`、このスプレッドシートは発注ナビ専用と割り切る）。列見出し「正規化カテゴリ」→「カテゴリ」。案件リストから「元カテゴリ表記」「個別カスタム文」列を削除（15列→13列）。応募文テンプレートは「カテゴリ×パーツ名」28行をやめ「カテゴリごとに応募文まるごと1行」に簡素化、変更履歴は同シート下段に自動追記
- **版3**（社長指示・今回）: 応募文テンプレートを1シートの縦持ちではなく **カテゴリごとに別シート**（`テンプレート_Web制作` 等）に分割。かつ **ライティング/その他/未分類はテンプレート対象外**（テンプレートシートを作らない）。ただし `案件リスト`/`集計` の分類自体は7カテゴリのまま変更なし（未分類バケツは分類・集計目的で必要なため残した — この判断はこちらの提案、社長の明示指示ではない点に注意）
- **版4**（社長指示・実データ投入後）: 実案件で未分類が多発（案件タイトルにしか手がかりが無いケースが多かった）。`normalizeCategory_` の入力を「元カテゴリ表記のみ」から**「案件タイトル＋元カテゴリ表記」**に変更し、キーワードも拡充（`システム`, `プラットフォーム`, `AI`, `DB` を追加）。既存の誤分類6件は手動修正を依頼済み（コードは今後の新着分にしか効かない）
- **予算・応募期限の自動取得は最初「見送り」の予定だった**（社長要望で技術検証のみ実施）: `UrlFetchApp.fetch()`で発注ナビの案件詳細URLを取得したところ、ログインページ（`発注ナビ-開発会社様用画面`）が返り、予算・応募期限は本文に含まれないことを確認。GASはブラウザのログインセッションを持たないため取得不可と判明。検証用ファイル`gas/ScrapeTest.gs`と追加した`script.external_request`権限は削除・撤回済み
- **版5**（社長指示・今回・最新）: 実データで未分類が多発したことを受け、キーワード分類の改良（版4）ではなく、**Claude Code + claude-in-chromeでの人力処理に一本化**する方針に転換。理由: GASのUrlFetchAppはログイン不可だが、社長の普段使いのChrome（ログイン済み）ならclaude-in-chromeで案件詳細ページを開けるため、予算・応募期限・カテゴリ（本文全体を見て判断）を同じ仕組みでまとめて解決できる。前提として「Claude Codeの入ったPCが常時起動している」ことに依存しない設計にする（社長の明示指示）＝ GASは新着検知だけ自動でやり、カテゴリ/予算/応募期限は空欄のまま作る。埋める作業は社長がセッション中に「lead-manager のリード処理して」と声をかけたときだけ、都度Claudeが実施する。手順は `docs/リード処理の手順.md` に新規作成
  - `gas/CategoryNormalizer.gs`（キーワード分類本体）を削除。`Config.gs`の`CATEGORY_RULES`も削除
  - `Parser_HatchuNavi.gs`は`category: ''`を返すだけにし、`normalizeCategory_`呼び出しを廃止
  - `GmailWatcher.gs`の「未分類警告ログ」ブロックを削除（分類自体をしなくなったため不要に）
  - **CATEGORIES / TEMPLATE_CATEGORIES はそのまま維持**（集計シートの行・テンプレートシートの分類先として引き続き必要。Claudeが手動処理する際もこの7分類から選ぶ）

### 実装した内容（版5・最新、要Apps Script再貼付）

- `gas/Config.gs` — 定数・`TEMPLATE_CATEGORIES`（テンプレート対象4分類）・プラットフォーム設定。カテゴリ判定ロジックは削除済み
- `gas/Parser_HatchuNavi.gs` — 発注ナビ配信メールのパース（案件No・タイトル・URL・予算/応募期限を正規表現抽出、予算/応募期限はメール本文にあれば拾うだけのbest-effort）。カテゴリは常に空文字

### 設計判断のメモ（後で見返す用）

- **集計の転換率はステータス列だけを見て算出**（応募日等の日付列は分母判定に使っていない）。「応募済以降」等は
  現在のステータスが該当ステージ以上かどうかで判定するシンプルな方式。失注が商談前後どちらで起きたかまでは
  区別しない（案件リストの備考欄に手動でメモする運用でカバーする想定）
- スプレッドシートは container-bound スクリプト（先にスプレッドシートを作り、拡張機能→Apps Scriptでコードを貼る）。
  slack-attendance と同じ「コピペでデプロイ」方式。clasp等のCLIデプロイは使っていない
- 今回シート名からプラットフォーム接頭辞を外したため、将来2サイト目を足す時は「別スプレッドシートに切り出す」か
  「その時点でまた接頭辞を付け直す」かの判断が必要（`gas/Config.gs` のコメントに書いてある）
- リネーム前の古いシート（`発注ナビ_案件リスト` 等）が版2セットアップ時に残留 → 社長が削除して解消済み
