# lead-manager — 案件獲得の営業パイプライン管理ツール

**自社の営業活動を管理するツール**（納品先のある受託案件ではない）。案件サイトからの配信メールを起点に
「応募 → 返信 → 商談 → 成約」を Google スプレッドシート上で一元管理し、どんな応募文・提示が
返信/商談化/成約につながりやすいかをカテゴリ別の転換率として蓄積・考察する。

## 対象サイト

- **発注ナビ**（実装済み）: `mo-hnavi@ml.itmedia.co.jp` からの新着案件配信メールを GAS が15分ごとに監視し、
  自動でスプレッドシートに1行追記する
- クラウドワーク・Upwork 等（未実装）: `gas/Config.gs` の `PLATFORMS` にエントリを追加すれば同じシート雛形で
  拡張できる構造にしてある。ただし Upwork のように配信メールが無いサイトは Gmail 監視とは別の取り込み経路が要る。
  現行のスプレッドシートは発注ナビ専用（シート名にプラットフォーム接頭辞なし）なので、2サイト目を足す際は
  シート名を分けるか別スプレッドシートに切り出す

## 構成

| パス | 内容 |
|---|---|
| `gas/` | Apps Script 一式（Gmail監視・メール解析・シート書き込み・初期セットアップ）。container-bound スクリプトとしてコピペでデプロイする |
| `docs/セットアップ手順.md` | 初回デプロイ・OAuth権限付与・トリガー設定の手順書 |
| `docs/リード処理の手順.md` | カテゴリ・予算・応募期限をClaude Code + claude-in-chromeで埋める手順 |
| `docs/進捗.md` | 進捗管理の正本（現在地・Next actions・Blockers） |

## スプレッドシート構成（発注ナビ専用）

1. **案件リスト** — 配信検知〜成約/失注までの案件ごとの状態（13列、ステータスはプルダウン）。
   GASが自動で入れるのは配信日時・案件No・タイトル・URL・ステータス（配信検知）のみ。
   **カテゴリ・予算・応募期限は空欄のまま作られる**（下記参照）
2. **テンプレート_Web制作 / テンプレート_システム開発 / テンプレート_デザイン / テンプレート_マーケティング** —
   カテゴリごとに応募文まるごと1本（A2）＋編集すると自動で積み上がる変更履歴（5行目以降）。
   ライティング/その他/未分類は分類・集計はするがテンプレートは作らない
3. **集計** — カテゴリ別（7分類すべて）の返信率・商談化率・成約率（COUNTIFSで自動算出）＋考察メモ

## カテゴリ・予算・応募期限の埋め方

発注ナビの案件詳細ページはログインが必要で、GAS（`UrlFetchApp`）はブラウザのログインセッションを持てず
自動取得できないことを検証済み。そのため **GASでは分類・取得をしない**。代わりに、Claude Codeセッション中に
claude-in-chromeでログイン済みのブラウザタブを操作し、案件詳細を読んでカテゴリ・予算・応募期限を埋める
（都度手動トリガー。詳しくは `docs/リード処理の手順.md`）。重複防止・変更履歴の記録・集計はスプレッドシート側で
完結しており、Anthropic API 等の LLM API 呼び出しには依存しない。

セットアップは `docs/セットアップ手順.md` を参照。
